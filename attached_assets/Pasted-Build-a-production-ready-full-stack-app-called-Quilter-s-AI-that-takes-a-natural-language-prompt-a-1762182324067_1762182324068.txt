Build a production-ready full-stack app called “Quilter’s AI” that takes a natural-language prompt about a quilt and returns 10–20 design options, each with: mockup image (SVG), materials estimate (yardage), cut list, piecing steps, block diagrams, assembly layout, backing/batting/binding calculations, suggested quilting motifs, difficulty/time, and printable PDFs (templates + instructions).

# Tech Stack
- Frontend: React + TypeScript + Vite
- Backend: Python 3.11 + FastAPI
- AI: OpenAI API (text) for interpreting user prompt → structured spec; key via env var OPENAI_API_KEY
- Generators: Pure-Python algorithms create SVG mockups and compute quilting math; WeasyPrint or ReportLab for PDFs
- Data: SQLite via SQLModel (sessions & saved designs)
- Auth: optional cookie session (local only; no third-party)
- Build/Run: one-click with uvicorn + vite concurrently; include .replit and replit.nix

# Core User Flow
1) User enters a free-text prompt (e.g., “modern twin quilt, teal + charcoal, budget under $120, prefer rectangles, no triangles, mid-skill, machine piecing, 60x80in, boho vibe”).
2) Backend uses an AI “Prompt Interpreter” to convert the text into a normalized design spec:
   {
     "size": { "width_in": 60, "height_in": 80, "category": "twin" },
     "style_tags": ["modern","boho","minimal"],
     "palette": ["teal","#333333","white"],
     "budget_usd": 120,
     "constraints": { "shapes": ["rectangles"], "avoid": ["HST"] },
     "skill_level": "intermediate",
     "piecing": "machine",
     "sashing": true/false,
     "border": 0|inches,
     "binding_bias": false,
     "prewash": true/false
   }
3) Generator produces 10–20 variations by combining block libraries + layout strategies, honoring constraints, then ranks for fit vs prompt. For each variation, return:
   - SVG top-view mockup at 1000px wide (export PNG preview too)
   - Quilt math (yardage, cut list per fabric, binding/backing/batting)
   - Piecing steps (ordered), block assembly diagrams (SVG), row/column plan
   - FPP (foundation paper piecing) PDFs if applicable, otherwise rotary cutting templates
   - Estimated time & difficulty (1–5), scrap-friendly flag
   - Optional quilting motifs (e.g., echo, crosshatch, baptist fan) with simple line overlays

# Quilt Math Requirements
- Seam allowance: 1/4 inch standard; all piece sizes add seam allowances
- WOF (usable): default 40–42 inches; allow override in settings
- Binding: perimeter + 10% slack; default strip width 2.5"
- Backing: quilt top + 4–6" overhang each side; recommend pieced backing plan
- Batting: quilt top + 2–4" each side
- Shrinkage options: 0–5%
- Yardage rounding: to nearest 1/8 yard
- Piece nesting across WOF with waste estimates
- Prebuilt size presets: baby (36x42), throw (54x72), twin (60x80), full/queen (90x96), king (108x108)

# Block/Pattern Library (starter set)

# Layout Strategies

  row-of-rows, on-point with sashing, negative space emphasis.

# Frontend UI/UX

- Results grid (10–20 cards): SVG/PNG preview, key stats, tags, “Open”, “Save”, “Export PDF”
- Detail view: tabs → Overview, Cut List, Steps, Templates, Layout Map, Quilting Motifs
- Palette tools: color picker, image palette extractor (upload a photo to sample 5–8 colors)

- Export: single ZIP with PDFs (instructions + templates), SVGs, and a CSV cut list

# Backend API (FastAPI)
- POST /api/interpret → {prompt} → normalized spec (calls OpenAI; include system prompt crafting)
- POST /api/generate → {spec, count=12} → array of DesignOption
- GET  /api/designs/:id → returns full design w/ assets
- POST /api/export/pdf → returns merged PDF for a design
- POST /api/export/zip → returns ZIP of all assets
- POST /api/palette/extract → image upload → HEX palette
- GET  /api/presets → sizes, WOF, binding, etc.
- POST /api/save, GET /api/saved

# AI Prompting (server-side, no PII)
- System prompt guides the interpreter to produce only the normalized spec with sizes, constraints, palette harmonies, and style tags; never invent fabric SKUs.
- If the user gives exact dimensions, those override presets.
- If constraints conflict (e.g., “no triangles” + “flying geese”), prefer constraints and suggest alternatives.
